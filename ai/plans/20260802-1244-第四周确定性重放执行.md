# 第四周确定性重放执行计划

> 本记录执行 [`research/plan.md` 第四周](../../research/plan.md#第四周确定性重放与-native-事务路径) 的七个步骤；每步独立提交并推送。由于 [`Week 3 G3 前置门控`](../../research/execution/week-03/results/step-07-week-03-gate.json) 已因 low overhead 超线而阻断，本周实现与实验仍完整执行，但最终决策必须 fail closed，不得把实现完成等同于 G3 通过。

## 目标与范围

- 冻结 schedule DSL v0.1，并从[八类 canonical trace](../../research/execution/week-03/results/step-04-canonical-traces.json)生成可执行 corpus。
- 建立 [`LockTable`](../../src/main/java/org/vanilladb/core/storage/tx/concurrency/LockTable.java#L48) 与 [`Transaction`](../../src/main/java/org/vanilladb/core/storage/tx/Transaction.java#L33) 的 gate-safe 台账。
- 实现 strict/partial-order replay、Native transaction harness、Direct/Native L1 投影与 G3 机器决策。
- 不实施 PCT，不修复等待注册清理问题，不改写 Week 3 原始证据。

## 方法依据与证据台账

| 来源 | 支持的设计决定 | 边界 |
| --- | --- | --- |
| [CHESS OSDI 2008](https://www.usenix.org/conference/osdi-08/finding-and-reproducing-heisenbugs-concurrent-programs) | 使用少量稳定 hook 控制调度，并保存可复现 schedule | 本实现不是 CHESS 的系统调用包装器，也不声称系统性穷举 |
| [DPOR POPL 2005](https://doi.org/10.1145/1040305.1040315) | 用依赖边与等价 linearization 表达偏序重放 | 本周只验证给定 DAG，不实现动态 backtracking 搜索 |
| [Java 17 Object.wait](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/Object.html#wait()) | 等待会释放当前对象 monitor，唤醒后仍需重新竞争；外部门控不得在持有 anchor monitor 时阻塞 | wall/nano time 仅作诊断，不推导跨线程全序 |
| [PCT ASPLOS 2010](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/asplos277-pct.pdf) | DSL 保留 seed 与策略扩展字段 | PCT 不进入本周验收或成功率分母 |

## 有序实施步骤

1. 新增 DSL schema、生成器、验证器、八 schedule corpus 与单元测试。
2. 审计每个 trace/lifecycle 点的 monitor、阻塞与风险；scheduler 对未知或不安全 gate fail closed。
3. 以稳定 source site 实现 strict scheduler，分类 divergence 并保留最短前缀。
4. 以事务内顺序、显式 edge、owner/release 因果和 barrier 实现 DAG scheduler，并验证至少两种合法线性化。
5. 通过 [`TransactionMgr.newTransaction`](../../src/main/java/org/vanilladb/core/storage/tx/TransactionMgr.java#L163) 实现 Native file/block/record harness，回传全部 worker outcome。
6. 建立 Direct/Native 到 L1 的投影规则，以允许执行集合而非原始事件逐条相等做差分。
7. 对八 schedule 的 high/low fresh JVM 重放各 30 次，收集 off/low 开销、loss、线程与内部状态残留，生成 fail-closed G3 决策。
